# Working preferences

- Keep code simple enough for the user to follow every step.
- Use clear names, normal spacing and one statement per line.
- Prefer straightforward setup() and loop() code for bench tests.
- Avoid extra helpers, abstractions, scripts and features unless needed.
- Put wiring, upload environment and expected result at the top of each test cpp.
- Explain hardware setup that cannot be made simpler, such as I2S.
- Keep written notes short and plain, like a work log. No elaborate docs or checklists.
